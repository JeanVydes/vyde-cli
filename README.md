# vyde — terminal client

Terminal client for Vyde account access through the gateway.

## Commands

```bash
vyde help
vyde ping                     is the service there
vyde login
vyde --dev login
vyde whoami
vyde logout
vyde serve                    the service, in the background
vyde manage grants list
vyde manage app list --org-id ORG_ID
```

The CLI is headless and scriptable. It shares one background service:

```
core/     the flow, protocol and domain types — no terminal or HTTP
vyde/
  platform/  the port over HTTP, and the OS keyring
  ipc.rs     the tunnel between the interface and the service
  headless.rs  the command parser and runner
```

The service owns the token in the kernel keyring and exposes a closed request/response protocol over a
socket in `$XDG_RUNTIME_DIR`. Commands start it when needed.

## Running it

### Install

The recommended installation downloads a signed release archive and verifies its SHA-256 checksum:

```bash
curl -fsSL https://docs.vyde.dev/install.sh | sh
```

The default destination is `~/.local/bin`. Override it with `VYDE_CLI_INSTALL_DIR`, or install a
specific release with `VYDE_CLI_VERSION=0.1.0`.

```bash
cargo run -- help
cargo run -- --dev ping         # local Docker stack
VYDE_GATEWAY_URL=https://api.vyde.test:8443 cargo run -- ping
```

Destructive management operations require `--yes`. Management results are emitted as JSON so they
can be consumed by scripts.

The base URL is `VYDE_GATEWAY_URL`, then `https://vyde.dev`. `--dev` selects
`https://api.vyde.test:8443`; an explicit variable wins. The OAuth UI defaults to
`https://identity.vyde.test:5173` in development and `https://identity.vyde.dev` otherwise.

The CLI uses Authorization Code + PKCE as a public OAuth client. Set `VYDE_OAUTH_CLIENT_ID` to the
ID generated by the Identity console; the selected client must be registered with the exact
loopback redirect URI `http://127.0.0.1:8675/callback` and have `authorization_code` and
`refresh_token` enabled. No client secret is stored or sent by the CLI.

When using the local HTTPS stack, the CLI automatically trusts `services/certs/ca.crt`. Set
`VYDE_CA_CERT_PATH` if the development CA is stored elsewhere.
